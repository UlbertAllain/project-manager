# Task 4.6 — Real-time Collaboration via WebSocket

## Summary
Implemented complete real-time collaboration system using Socket.IO WebSocket mini-service that broadcasts activity updates so multiple tabs/users see live changes.

## Files Created
1. `mini-services/activity-ws/package.json` — Separate bun project with socket.io dependency
2. `mini-services/activity-ws/index.ts` — Socket.IO server on port 3003 with activity/data-changed event broadcasting, project rooms
3. `src/lib/socket.ts` — Socket singleton utility (getSocket/disconnectSocket) for use in mutation hooks
4. `src/hooks/useActivitySocket.ts` — Frontend hook that connects to WS, listens for data-changed events, auto-invalidates React Query caches

## Files Modified
1. `src/hooks/useProjects.ts` — Added socket event emissions to useCreateProject, useUpdateProject, useDeleteProject
2. `src/hooks/useProject.ts` — Added socket event emissions to useUpdateProjectMutation, useDeleteProjectMutation
3. `src/hooks/useTransactions.ts` — Added socket event emissions to useCreateTransaction, useDeleteTransaction
4. `src/hooks/useComments.ts` — Added socket event emissions to useCreateComment
5. `src/hooks/useDuplicateProject.ts` — Added socket event emissions to useDuplicateProject
6. `src/app/page.tsx` — Integrated useActivitySocket() hook for authenticated users

## Architecture
- Mini-service runs on port 3003, connects via Caddy gateway using `/?XTransformPort=3003`
- Two connection patterns:
  - `useActivitySocket` hook: creates its own socket for listening to data-changed events (auto query invalidation)
  - `getSocket()` singleton: used by mutation hooks to emit events without creating duplicate connections
- Events: `activity` (broadcast notifications), `data-changed` (entity-based query invalidation), `join-project`/`leave-project` (room subscriptions)
